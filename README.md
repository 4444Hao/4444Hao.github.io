# 风过枝间

一个米白、绿树与安静文字的个人静态博客。顶部导航为「主页／随笔／短记／摘录／专题整理」。主页以标签关系图谱浏览全部内容，四个栏目直接展示对应笔记。当前 59 篇本地待审阅文章、2 篇草稿。尚未提交、推送或部署。

## 在 VS Code 中预览

首次在新电脑使用时，安装构建依赖：

```powershell
python -m pip install -r requirements.txt
```

按 Ctrl+Shift+B 运行「生成博客」，在「终端 → 运行任务」中选择「预览博客（8001）」。打开 http://127.0.0.1:8001/ 。也可以运行：

```powershell
python build.py
python -m http.server 8001 --bind 127.0.0.1 --directory docs
```

必须通过本地服务访问，不要双击 HTML。修改后重新构建并刷新网页；停止服务按 Ctrl+C。

## 只维护 Markdown

每篇文章的元数据放在 content/*.md 开头的 YAML 属性中，类似 Obsidian 的 Properties。新建 content/summer-walk.md：

```yaml
---
title: 夏日散步
slug: summer-walk
category: 随笔
tags:
  - 自然
  - 独处
  - 夏日
summary: 在风与树影之间，留下一段散步的记录。
updated: '2026-10-03'
draft: false
provenance: 个人记录
sourceNote: 个人记录。
---

这里开始写正文。
```

- 文件名与 slug 一致，使用小写字母、数字、连字符。已有 slug 保持不变。
- 分类为「随笔／短记／摘录／专题整理」。标签自由添加，不维护全站白名单；不重复计算同一篇的相同标签。通常每篇 2–4 个标签，也允许没有标签。
- summary 是列表摘要；updated 是本次内容维护日期，修改正文、摘要或标签时手动更新。已知写作日期可另加 date，未知则省略。
- draft: true 不生成页面，不参与统计或图谱。草稿仅在网站源码中保留，源码仓库公开时仍能被读到。
- 摘录填写 provenance 与 sourceNote；AI 协助整理单独标注。来源说明不代表事实已核实。
- order 可选，用整数指定无日期文章的顺序；不填则放在既有无日期文章后面，按文件名排序。已知日期文章优先，按日期倒序。

content/index.json 是构建生成的审阅索引，请不要在里面修改文章属性。原始 Obsidian 文件不自动同步、不被修改。

## 图谱如何生长

- 仅由公开文章汇总标签。新标签下一次构建后自动出现，最后一篇相关公开文章删除或改为草稿后消失。
- 节点大小按引用文章篇数计算，设置最小及最大尺寸。两标签共同出现在文章中便连线，共同篇数越多连线越明显。
- 页面打开时图谱轻轻调整并逐渐稳定；支持拖动、悬停关联高亮、键盘 Enter/空格选择。
- 标签筛选只在主页，点击已选标签取消；顶部按需显示标签、结果篇数、移除标签与清除入口。其他栏目通过真正的页面导航进入，不继承主页筛选。
- 手机可以切换「标签列表」。系统设置减少动态效果时，初始布局直接静止；也可手动暂停动态。关闭 JavaScript 仍能通过分页链接浏览全部文章。

图谱数据生成在 docs/assets/graph-data.json；运行时直接使用页面中的 SVG 数据，无须接口请求。没有后端、评论、登录、外部字体、CDN 或访问统计。


## 导航与分页

- 主页 `/`：介绍、统计、图谱和全部笔记，包括摘录。共 59 篇，默认 6 页。
- 随笔 `/essays/`：13 篇，2 页。
- 短记 `/notes/`：16 篇，2 页。
- 摘录 `/excerpts/`：24 篇，3 页。
- 专题整理 `/collections/`：6 篇，1 页。
- 每页 10 篇；新内容会在构建时自动增加分页。关于移到页脚。
- 普通分页是静态路径，例如 `/page/2/`、`/notes/page/2/`，无需 JavaScript 也可使用。
- 启用 JavaScript 时，在同页切换列表，翻页后停留在列表开头。浏览器返回、前进与刷新会保留对应页。
- 首页选中标签后回到结果第 1 页；翻页保留标签，例如 `/?tag=阅读&page=2#records`。清除标签恢复全部笔记第 1 页。旧的首页 category 查询链接仍兼容。
- 桌面显示页码，手机显示「上一页／第几页／下一页」。单页结果不显示分页控件。
- 全站统计计算所有公开文章，与当前页面或标签结果的篇数分开显示。

## 其他维护位置

- site.json：网站名称、简介、正式网址与四个分类。
- assets/style.css、assets/graph.css：正文与图谱布局样式。
- assets/filter.js、assets/graph.js：筛选及本地 SVG 图谱。
- CONTENT_REVIEW.md：内容审阅清单。
- docs/：构建产物，不直接编辑；构建前先校验所有文章，成功后才替换。

正文支持标题、列表、引用、表格、代码块和本地图片；Mermaid 保留为代码。原始 HTML 转义、不执行；Obsidian 双链需要先整理成普通 Markdown 链接。

字数包含摘录、表格与代码中的汉字、字母和数字，排除标题、元数据、链接网址、标点与空白。重复构建不改变更新时间。

## 验证与后续发布

构建测试在临时副本中运行，不更改真实文章：

```powershell
python -m unittest discover -s tests -v
```

先在本地审阅内容。确认公开范围后，再使用 VS Code 提交和推送源文件与 docs/。GitHub Pages 使用 main 分支的 /docs；Cloudflare Pages 可以连接同一仓库发布相同静态目录。正式网址变更时更新 site.json 后重新构建。本项目面向域名根路径。
